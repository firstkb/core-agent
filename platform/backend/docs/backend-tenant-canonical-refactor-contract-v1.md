# Tenant Canonical Refactor Contract v1

Status: accepted  
Date: 2026-04-15

## Purpose

This document defines the accepted canonical tenant database contract for the next tenant rebuild.

It is the source of truth for:

- `platform/backend/migrations/postgres/tenant/000_tenant_baseline.sql`
- `platform/backend/bundle/tenant_schema_full.sql`
- tenant-side canonical table naming
- the legacy-to-canonical column mapping contract

It is not the import implementation plan. That boundary is defined separately.

## Scope

Canonical tenant tables covered from `platform/backend/docs/MSSQL/*`:

- `users`
- `company`
- `companytype`
- `jobtype`
- `projects`
- `projectsaccess`
- `events`
- `mails`
- `state`

New canonical reference table:

- `timezone`

Tenant runtime tables kept in the same bundle:

- `public_code`
- `notification_template`
- `ps_model`
- `ps_view`

## Accepted Direction

The tenant database no longer uses legacy `<table_name>_<field_name>` as its runtime contract.

Accepted rules:

- keep table names where practical to reduce migration churn
- normalize columns to semantic lowercase `snake_case`
- remove table prefixes from canonical column names
- rename ambiguous legacy fields to domain-meaningful names
- do not support dual legacy and canonical column layouts in runtime tables

Examples:

- `users_firstname -> first_name`
- `users_act -> active`
- `company_type -> company_type_id`
- `events_record -> record_id`
- `mails_recid -> target_record_id`

## Global Rules

### Table Names

Canonical tenant table names:

- `state`
- `timezone`
- `companytype`
- `jobtype`
- `company`
- `users`
- `projects`
- `projectsaccess`
- `events`
- `mails`
- `public_code`
- `notification_template`
- `ps_model`
- `ps_view`

### Column Naming

Canonical column rules:

- no table prefix in column names
- lowercase ASCII `snake_case`
- foreign keys use `<target>_id`
- booleans use explicit positive names
- time columns should describe meaning, not storage history

Examples:

- `id`
- `tenant_id`
- `company_type_id`
- `first_name`
- `system_access`
- `occurred_at`

Rejected in canonical tenant tables:

- `users_firstname`
- `projects_datebegin`
- `events_record`
- `mails_recid`
- abbreviations such as `act`, `desc`, `num` when the intended meaning is broader

### System Columns

Canonical mutable tenant tables use:

- `id bigint generated by default as identity primary key`
- `tenant_id bigint not null` on tenant-owned mutable tables
- `guid uuid not null default gen_random_uuid()` on externally referenced business entities
- `created_at timestamptz not null default now()`
- `updated_at timestamptz not null default now()`

Freshness rule:

- `updated_at` is the canonical replacement for legacy SQL Server `rowstamp`
- mutable canonical tables attach shared `set_updated_at()`
- the same trigger contract applies to Form Builder managed runtime tables

Not part of the canonical tenant contract:

- MSSQL `rowstamp`
- PostgreSQL `_row_version`

### GUID Policy

`guid` is required in the current canonical bundle for:

- `companytype`
- `jobtype`
- `company`
- `users`
- `projects`
- `events`
- `mails`

`guid` is not part of the current canonical bundle for:

- `projectsaccess`
- `state`
- `timezone`
- `public_code`
- `notification_template`

### Tenant Isolation

Tenant-owned mutable tables remain tenant-scoped and RLS-protected:

- `companytype`
- `jobtype`
- `company`
- `users`
- `projects`
- `projectsaccess`
- `events`
- `mails`

Global reference tables in v1:

- `state`
- `timezone`

### Migration Policy

Accepted direction:

1. canonical tenant bundle defines the final runtime schema
2. legacy MSSQL and legacy PostgreSQL become import-only sources
3. import maps legacy columns explicitly into canonical columns
4. runtime code eventually targets only the canonical schema

The canonical runtime does not preserve both old and new column names.

## Canonical Table Contracts

### `state`

Purpose:

- shared reference list of U.S. states and territories

Canonical columns:

- `id bigint primary key`
- `code text not null`
- `name text not null`

Rules:

- legacy ids `1..51` are preserved to simplify import
- legacy `state_name` is split into `code + name`

### `timezone`

Purpose:

- shared reference list for timezone selection

Canonical columns:

- `id bigint generated by default as identity primary key`
- `name text not null`

Rules:

- current canonical timezone contract is display-only
- do not add DST or offset logic until a real timezone behavior contract exists
